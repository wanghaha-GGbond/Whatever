# 移动端 AI 本地生活决策产品 UI/UX 设计规范

## 一、产品概览

### 产品定义

帮助用户描述兴趣后，结合定位搜索附近地点，并通过 AI 筛选、讨论、抓阄，最终随机选出一个可立即出发的目的地。

### 设计要求

1. **整体风格**：轻松、干净、带一点探索感和游戏化，不要像传统地图工具
2. **布局方式**：卡片式布局，高留白，圆角体系，轻阴影
3. **首页结构**：主视觉输入框 + 快捷标签 Chips + 历史记录入口 + 明确 CTA
4. **候选页**：地点卡片列表，包含距离、预算、AI 探店摘要、风险标签，带吸顶筛选栏
5. **结果页**：突出最终目的地，加入抓阄动画和情绪反馈，保留备选方案
6. **体验关键词**：可解释性、约束随机、决策降噪、探索感、低认知负担

### 视觉风格

- **主风格**：iOS 原生轻工具风
- **辅助气质**：城市探索感
- **点缀方式**：温和游戏化

关键词：
轻、准、短、可信、有一点趣味、不打扰

视觉要求：
- 大面积留白
- 卡片式布局
- 大圆角
- 轻阴影
- 主色使用偏蓝绿色，强调色使用暖黄色
- 中性色背景保持克制
- 不做攻略感，不做信息堆砌
- 不要像传统地图或点评社区
- 结果页需要有“被拍板”的感觉
- 人格试玩模块要有轻微趣味，但不能娱乐化过头

组件风格：
- 自然语言输入框作为首页主视觉
- 候选地点使用高信息密度但可扫读的卡片
- 结果页突出一个地点
- 人格切换使用胶囊 Tabs
- 底部主 CTA 明确且固定

## 三、UI/UX 总原则

### 1. 产品气质

定位成 **AI 决策助手 + 本地生活轻工具**，不是地图，不是点评，不是攻略社区。

### 2. 体验目标

用户打开后应在 **30 秒内完成一次“去哪”的决策**。

### 3. 设计关键词

**轻决策、城市探索、温和游戏化、iOS 原生感、卡片化、高留白、强 CTA**

### 4. 核心体验路径

**说需求 → 看少量候选 → 抓阄 → 选人格试玩 → 出结果 → 导航**

---

## 四、信息架构

首版建议 4 个页面就够：

1. **首页**：发起一次地点决策
2. **候选页**：展示 Top 5 高质量候选
3. **结果页**：展示最终地点 + 人格试玩
4. **历史页**：看过去抽中过的地点

底部导航建议只保留 2 个入口：

* **发现**
* **历史**

不要加“社区”“消息”“攻略”，会把产品做重。

## 五、核心页面方案

## 1）首页：发起决策

### 页面目标

让用户最快说出需求，并开始筛选。

### 页面结构

从上到下：

1. **顶部定位栏**

   * 文案：`当前位置 · 虹桥人才公寓附近`
   * 右侧：切换位置 icon

2. **主标题区**

   * 标题：`今天想去哪？`
   * 副标题：`说一句你的状态，AI 帮你定一个地方`

3. **自然语言输入框**

   * 占位文案：
     `比如：骑车20分钟内，预算50，适合一个人安静待会`
   * 支持语音输入图标

4. **快捷条件 Chips**

   * 场景：`独处 / 约会 / 朋友`
   * 通勤：`步行 / 骑车 / 地铁`
   * 预算：`¥0-30 / ¥30-50 / 不限`
   * 氛围：`安静 / 热闹 / 有新鲜感 / 好看`

5. **最近一次记录**

   * 小卡片：地点名 + 时间 + “再抽一次”

6. **主 CTA**

   * 按钮文案：`帮我选一个`

### 交互重点

* 用户可以只输入一句话，不强制点标签
* 标签是补充，不是主操作
* CTA 固定在屏幕下方更好，单手操作更顺

### 首页线框

```text
[当前位置 · 虹桥人才公寓附近 ▼]

今天想去哪？
说一句你的状态，AI 帮你定一个地方

[ 骑车20分钟内，预算50，适合一个人安静待会      🎤 ]

[独处] [约会] [朋友]
[步行] [骑车] [地铁]
[¥0-30] [¥30-50] [不限]
[安静] [热闹] [有新鲜感] [好看]

最近一次
上生新所 · 周六 16:20

              [帮我选一个]
```

## 2）候选页：AI 筛选结果

### 页面目标

建立“AI 认真筛过”的信任感，但不让用户重新陷入选择困难。

### 页面结构

1. **吸顶筛选栏**

   * `预算`
   * `距离`
   * `类型`
   * `重筛`

2. **AI 筛选摘要条**

   * 文案示例：
     `已排除超预算、过远、当前不适合的地点，保留 5 个候选`

3. **候选地点卡片列表（Top 5）**
   每张卡片只放决策信息：

   * 地点名
   * 类型
   * 到达时间
   * 预算
   * AI 简短判断
   * 风险标签（可选）

4. **底部固定 CTA**

   * 文案：`开始抓阄`

### 单张卡片结构

* 标题：`新泾公园`
* 副信息：`公园 · 骑车12分钟 · ¥0`
* AI 判断：`现在去比较轻松，适合一个人待一会`
* 风险标签：`傍晚人会变多`

### 候选页交互

* 支持左右滑删不需要，没必要
* 点击卡片只展开更多判断，不进入详情页
* 重点不是浏览地点详情，而是推动抓阄

### 候选页线框

```text
[预算▼] [距离▼] [类型▼]                       [重筛]

已排除超预算、过远、当前不适合的地点，保留 5 个候选

┌────────────────────┐
新泾公园
公园 · 骑车12分钟 · ¥0
现在去比较轻松，适合一个人待一会
[傍晚人会变多]
└────────────────────┘

┌────────────────────┐
社区咖啡店
咖啡 · 骑车10分钟 · ¥28
距离近，坐一小时不会有负担
[周末3点后可能满座]
└────────────────────┘

                [开始抓阄]
```

## 3）结果页：最终地点 + 人格试玩

### 页面目标

给用户一个明确结果，并通过“人格试玩”降低犹豫。

### 页面结构

1. **抓阄完成动画区**

   * 简短转盘/抽签动效，1.2 秒内结束
   * 文案：`今天去这里`

2. **最终地点大卡**

   * 地点名
   * 类型
   * 距离/到达时间
   * 预算
   * 入选理由

3. **人格选择区**
   采用横向 Tabs / Chips：

   * `独处型`
   * `探索型`
   * `务实型`
   * `审美型`

4. **人格试玩内容卡**
   用户点一个人格后，展示：

   * 玩后感
   * 风险提醒
   * 结论

5. **底部操作区**

   * `去导航`
   * `重新抽`
   * `收藏`

### 人格试玩内容格式

以 `独处型` 为例：

* 玩后感：`这里不会逼你社交，适合一个人慢慢待着。`
* 风险：`傍晚可能没有你想的那么空。`
* 结论：`我会去。`

### 结果页交互重点

* 默认选中“最贴近用户当前场景”的人格
* 用户切人格时，内容卡平滑切换
* 不展开成长攻略，不给路线组合

## 4）历史页

### 页面目标

形成留存和复用。

### 页面结构

* 历史地点列表
* 每条包含：

  * 地点名
  * 时间
  * 当时条件摘要
  * 满意度标签
  * 再抽一次

### 价值

* 让用户看到自己的“出门记录”
* 为后续偏好学习提供反馈入口

## 六、关键交互设计

## 1. 抓阄交互

不要做赌场式重动画，建议做 **轻微仪式感**：

* 候选卡片收缩成 5 个代号点
* 点位快速切换高亮
* 最终落在一个地点
* 震动反馈一次

目标：**有决定感，不花哨**

## 2. 人格切换交互

* 采用顶部横向人格 Chips
* 切换后内容卡做 150–200ms 淡入/横滑
* 当前选中人格有实心底色

## 3. 输入交互

* 输入一句话即可开始
* 当用户没写完整时，系统自动补全结构化参数
* 不强迫填表单

## 4. 重抽逻辑

* 重抽只在当前 Top5 内重算一次，避免无限跳结果
* 文案：`换一个也行`

## 七、视觉系统建议ϵ补充）

## 1. 色彩

建议一主一辅：

* **主色**：偏清爽蓝绿，表达探索和出发感
* **强调色**：偏暖黄，用于“抓阄完成”“结果高亮”
* **中性色**：大面积留白 + 浅灰背景

避免大红大紫，会太像娱乐产品。

## 2. 字体层级

* H1：页面标题
* H2：地点名 / 模块标题
* Body：AI 判断、人格试玩文案
* Caption：距离、预算、类型

重点：地点名要大，判断语要短。

## 3. 圆角与阴影

* 卡片圆角：16–20
* 主按钮圆角：14–18
* 阴影轻，不要厚重浮夸
* 可适当用毛玻璃做顶部定位栏或底部 CTA 区

## 八、状态设计

这部分很关键，决定产品是否完整。

## 1. 首页空状态

* 未开启定位：`先打开定位，AI 才能帮你找附近`
* 无历史记录：隐藏历史模块即可

## 2. 加载状态

出现在“AI 正在筛选”和“抓阄中”：

* 文案：

  * `在附近帮你找地方…`
  * `让 AI 先替你筛一轮…`
* 用 Skeleton + 轻动效，不用转菊花太久

## 3. 无结果状态

例如用户条件过严：

* 文案：
  `附近没找到完全符合的地点，已自动放宽一点距离`
* 提供按钮：

  * `放宽条件`
  * `重新输入`

## 4. 人格试玩加载状态

切换人格时若需重新生成：

* 保持结果卡不动
* 试玩内容卡局部 loading
* 避免整个页面闪烁

## 七、文案风格规范

你的产品文案必须是 **拍板型**，不是“劝导型”“攻略型”。

### 推荐语气

* `今天去这里`
* `这个更适合你现在`
* `已替你排除不合适选项`
* `换一个也行`
* `让不同人格先替你感受一下`

### 不推荐

* `建议你先去这里再去那里`
* `这边很适合拍照打卡喝咖啡散步`
* `为你精心规划了半天路线`

## 八、首版最重要的 8 个组件

1. **Location Bar**：顶部定位条
2. **Prompt Input**：自然语言输入框
3. **Chips**：场景/预算/通勤标签
4. **Candidate Card**：候选地点卡片
5. **Result Card**：最终地点大卡
6. **Persona Tabs**：人格切换标签
7. **Persona Review Card**：人格试玩卡
8. **Primary CTA**：主按钮

## 十一、首版 UX 成功标准

首版不看“内容深度”，看这 4 个：

1. 用户能不能在 **30 秒内完成一次决策**
2. 用户会不会点 **去导航**
3. 用户会不会使用 **重新抽**
4. 用户会不会点击 **人格试玩**

只要这四个行为成立，你这个产品的核心体验就是通的。

## 十、最终定稿版 UI/UX 结论

### 首页

一句话输入需求，快速发起决策

### 候选页

只展示 5 个高质量候选，建立信任，不让用户再次纠结

### 结果页

只给 1 个地点，用户手动切换人格 Agent，看“虚拟玩后感”，然后直接导航

### 整体风格

**轻、准、短、直接，有一点点命运感，但不做攻略感**

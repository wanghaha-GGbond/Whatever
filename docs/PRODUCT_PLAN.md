# Whatever 产品全局规划

## 一、产品愿景与定位

### 核心主张
Whatever 不是推荐引擎，是**决策焦虑的解药**。

传统推荐工具（大众点评、小红书）给用户更多选择，反而加重焦虑。Whatever 的逻辑是反过来的：**帮你选、替你看、给你理由接受它**。

### 价值公式
> 决策解放（抓阄替你选）+ 体验前置（人格替你逛）+ 情绪确认（多视角给你理由）= 选完不后悔

### 目标用户画像
一二线城市 20-35 岁白领，核心特征：
- 选择过剩：打开外卖/点评 app 反复滑但选不出来
- 时间有限：午休就 1 小时，周末不想浪费在"决定去哪"上
- 需要理由：不是没能力选，是选完了怕后悔，需要一个"说法"

### 竞品空位
| 产品 | 能力 | 缺什么 |
|------|------|--------|
| 大众点评 | 信息最全 | 越看越焦虑，不帮你做决定 |
| 小红书 | 内容种草 | 种草≠拔草，看完更纠结 |
| 随机选择器 | 帮你选 | 选完没有理由，心里不服 |
| **Whatever** | **选 + 体验 + 理由** | **闭环** |

## 二、场景分层与渗透节奏

不做"附近去哪"的大而全，而是**一个场景打透再扩**。

### 场景优先级排序

| 优先级 | 场景 | 频次 | 决策痛感 | 验证难度 | 目标阶段 |
|--------|------|------|----------|----------|----------|
| P0 | 工作日午餐 | 日频 | 极高（天天纠结）| 低 | Beta |
| P1 | 咖啡/下午茶 | 周频 | 中 | 低 | V1 |
| P2 | 周末去哪玩 | 周频 | 高 | 中 | V1.5 |
| P3 | 约会/聚餐 | 月频 | 极高 | 高 | V2 |
| P4 | 带娃/带父母 | 月频 | 高 | 高 | V2+ |

### P0 场景深挖：工作日午餐

**为什么先打这个场景：**
- 频次最高，每天都发生，容易养成习惯
- 地理范围小（公司附近 1-2km），POI 搜索精度够用
- 决策时间窗口短（10 分钟内要定），产品价值最直接
- 反馈闭环快（吃完就能评价），偏好学习迭代快

**需要打透的细分意图：**
| 用户表达 | 解析为 | 筛选侧重 |
|----------|--------|----------|
| "随便吃点" | 无偏好，快速决策 | 距离近 + 评分稳定 |
| "想吃辣的" | 口味偏好 | 品类标签匹配 |
| "不想排队" | 时间敏感 | 小店/非高峰时段 |
| "带客户吃饭" | 场合需求 | 人均 + 环境评分高 |
| "今天想吃好的犒劳自己" | 情绪驱动 | 人均上浮 + 评分高 |
| "吃点没吃过的" | 探索欲 | 排除历史去过的 + 新店优先 |
| "省点钱" | 预算敏感 | 人均低 + 性价比高 |

## 三、核心体验架构

### 全链路用户旅程

```
┌─────────────────────────────────────────────────────────┐
│  1. 说状态                                               │
│  用户输入一句话描述需求（语音/文字）                      │
│  "今天中午想吃点辣的，别太远"                             │
├─────────────────────────────────────────────────────────┤
│  2. AI 解析                                              │
│  意图解析 → 结构化查询条件                                │
│  {口味:辣, 距离:<1km, 场合:日常, 预算:不限}              │
├─────────────────────────────────────────────────────────┤
│  3. 搜索筛选                                             │
│  高德 POI + 多维评分 + 用户偏好修正 → Top 5              │
├─────────────────────────────────────────────────────────┤
│  4. 候选展示                                             │
│  5 家店卡片，每家一句话概要                               │
│  用户可以淘汰不想要的（可选，不强制）                     │
├─────────────────────────────────────────────────────────┤
│  5. 抓阄决策  ← 核心仪式感                               │
│  动画 + 结果揭晓                                         │
│  心理暗示："命运帮你选了这家"                             │
├─────────────────────────────────────────────────────────┤
│  6. 体验切片  ← 核心差异化                               │
│  多人格 AI 云游，碎片化体验流                             │
│  给用户"接受这个选择"的理由                               │
├─────────────────────────────────────────────────────────┤
│  7. 行动                                                 │
│  一键导航 / 分享给朋友 / 不满意重新抓                    │
├─────────────────────────────────────────────────────────┤
│  8. 反馈闭环                                             │
│  去过之后评价（简单打分 + 一句话）                        │
│  喂入偏好系统，下次推荐更准                               │
└─────────────────────────────────────────────────────────┘
```

### 各环节体验目标

| 环节 | 时间预期 | 体验关键词 | 失败体验 |
|------|----------|-----------|----------|
| 说状态 | 3 秒内输入完 | 零门槛，说人话 | 要填表、选分类 |
| AI 解析 | <1 秒 | 无感，用户不需要知道 | 解析错了且没法纠正 |
| 搜索筛选 | 2-3 秒 | 等待有反馈（动画） | 白屏干等 |
| 候选展示 | 5-10 秒浏览 | 一眼能看出区别 | 5 家看起来一样 |
| 抓阄决策 | 3-5 秒动画 | 仪式感、命运感 | 太快没感觉 |
| 体验切片 | 15-30 秒浏览 | 有趣、有用、想分享 | 像机器生成的废话 |
| 行动 | 1 秒跳转 | 丝滑衔接 | 导航链接打不开 |

## 四、体验切片系统设计

### 设计原则
1. **碎片化**：不是一篇评测，是 3-4 个"瞬间"
2. **人格驱动**：同一家店，不同人格关注完全不同的东西
3. **情绪优先**：先传递感受，再给信息
4. **可分享**：每个切片独立成立，可以单独截图分享

### 切片结构

每个人格输出 3-4 个切片，每个切片包含：

```
┌─────────────────────────────────┐
│  📍 场景标签（到门口/点单/体验中/离开时）│
│                                 │
│  💬 一句话体验（≤30字）          │
│                                 │
│  🏷️ 情绪标签（如：值得等、有惊喜） │
│                                 │
│  🖼️ 配图（V2 引入，来自社交平台） │
└─────────────────────────────────┘
```

### 切片节奏模板（以午餐场景为例）

| 切片序号 | 场景 | 内容方向 |
|----------|------|----------|
| 1 | 🚶 到门口 | 第一印象：排队情况、门面、氛围 |
| 2 | 📋 点单 | 推荐点什么、避什么雷 |
| 3 | 🍽️ 开吃 | 核心体验：味道、份量、亮点或槽点 |
| 4 | 🚪 总结 | 评分 + 一句话定论 |

### 信息密度控制策略

| 层级 | 用户行为 | 看到什么 |
|------|----------|----------|
| L1 扫一眼 | 不点开 | 人格头像 + 评分 + 一句话结论 |
| L2 随便看看 | 点开切片流 | 4 个切片，每个一两句话 |
| L3 感兴趣 | 点具体切片 | 展开详情（V2: 配图 + 来源链接）|

用户大多数时候停留在 L1-L2，信息密度刚好。想深挖的人有 L3 接住。

## 五、人格系统设计

### 设计原则
- 人格不是"换个语气说同样的话"，而是**关注点完全不同**
- 每个人格有明确的"决策权重"，对应不同用户心态
- 共 8 个人格：4 个通用（周末去哪玩）+ 4 个午饭专项（Beta 主场景）

### 通用人格（周末出行场景）

#### 🍔 老饕（吃货人格）
- **关注点**：味道、食材、烹饪水平、隐藏菜单
- **口头禅风格**：热情、直接、有点贪心
- **决策权重**：口味 > 一切
- **适用用户心态**："今天就想吃顿好的"
- **午餐场景示例**：
  - 到门口："老板在灶上，手艺人的店，稳了"
  - 点单："招牌红烧肉必点，加个虎皮尖椒不亏"
  - 开吃："肉炖得够烂，酱香到位，米饭得加"
  - 总结："8/10，唯一的问题是吃完不想上班"

#### ⚡ 效率党
- **关注点**：等餐时间、距离、动线、出餐速度
- **口头禅风格**：干脆、量化、不废话
- **决策权重**：时间 > 一切
- **适用用户心态**："赶紧吃完回去干活"
- **午餐场景示例**：
  - 到门口："步行 6 分钟到，没排队，进"
  - 点单："点墙上推荐的，出餐最快"
  - 开吃："15 分钟吃完，份量刚好不撑"
  - 总结："全程 35 分钟搞定，效率拉满"

#### 💰 精算师
- **关注点**：人均、份量、性价比、隐形消费
- **口头禅风格**：精明、算账、偶尔吐槽
- **决策权重**：性价比 > 一切
- **适用用户心态**："省着点花"
- **午餐场景示例**：
  - 到门口："没有低消，已经赢了"
  - 点单："28 块的套餐比 22 的多一个菜，选贵的反而划算"
  - 开吃："这份量，在这个地段，算良心了"
  - 总结："人均 31，同品质隔壁要 45，赚到了"

#### 🎭 氛围感
- **关注点**：环境、光线、音乐、适不适合坐着聊天/发呆
- **口头禅风格**：感性、注重细节、偶尔文艺
- **决策权重**：体验感 > 一切
- **适用用户心态**："不只是填饱肚子"
- **午餐场景示例**：
  - 到门口："原木门头，进去有植物墙，加分"
  - 点单："菜单设计得不错，有审美的店"
  - 开吃："窗边位有自然光，适合发 15 分钟呆"
  - 总结："吃的一般，但这个空间值得再来坐坐"

### 午饭专项人格（Beta 主场景）

#### 🍔 老饕
- **关注点**：味道、食材、烹饪水平、隐藏菜单
- **决策权重**：口味 > 一切
- **适用心态**："今天就想吃顿好的"

#### ⚡ 效率党
- **关注点**：等餐时间、距离、动线、出餐速度
- **决策权重**：时间 > 一切
- **适用心态**："赶紧吃完回去干活"

#### 💰 精算师
- **关注点**：人均、份量、性价比、隐形消费
- **决策权重**：性价比 > 一切
- **适用心态**："省着点花"

#### 🎭 氛围感
- **关注点**：环境、光线、音乐、适不适合坐着聊天/发呆
- **决策权重**：体验感 > 一切
- **适用心态**："不只是填饱肚子"

### 人格扩展规则（V2+）
- 特定场景可激活**场景人格**：约会场景 → "恋爱军师"、带娃场景 → "遛娃达人"
- 用户使用频率高的人格，权重自动上浮
- 远期可考虑用户自定义人格

## 六、内容丰富度路线图

### 三个阶段，逐步升级

```
Phase 1（Beta）         Phase 2（V1）           Phase 3（V2）
纯文本切片              文本 + 静态图片          富媒体切片
─────────────          ─────────────           ─────────────
AI 基于 POI 元数据      引入 Web Search          社交平台内容聚合
生成体验描述            抓取真实评价/图片        小红书/微博/抖音
                       作为切片素材              图片+短视频嵌入

信息来源：              信息来源：               信息来源：
• 高德 POI 数据         • 高德 POI 数据          • 高德 POI 数据
• 店铺基础信息          • 搜索引擎评价摘要       • 小红书笔记
• AI 想象力             • 公开图片               • 微博/抖音内容
                       • AI 整合                 • 用户 UGC
                                                • AI 编排
```

### Phase 1 策略：纯 AI 生成，但要"像真的去过"

**关键问题**：没有真实数据，AI 怎么让切片不像瞎编？

**方法**：
1. 充分利用高德 POI 返回的结构化数据（品类、评分、人均、营业时间、距离）
2. 给 AI 的 prompt 中注入"推理链"——基于人均价格推断装修水平，基于品类推断出餐速度
3. 切片文案用**推测性表达**而非断言："评分 4.5，大概率不会踩雷"而不是"味道特别好"
4. 当 AI 没有信息时，诚实说"这家没太多信息，但距离近，试错成本低"

### Phase 2 策略：Web Search 注入真实性

**目标**：切片中出现真实评价片段和图片
**技术路径**：
- 在 /recommend/pick 和 /persona/review 之间加一步：Web Search Agent
- 搜索 "{店名} {地址} 评价" 或 "{店名} 怎么样"
- 提取关键评价片段（口味、环境、服务相关）喂给人格 AI
- 抓取公开图片作为切片配图
**风险**：搜索延迟会拉长等待时间 → 可以先出文本切片，图片异步加载

### Phase 3 策略：社交平台内容聚合

**目标**：切片中嵌入小红书/微博/抖音的真实内容
**技术挑战**：
| 平台 | 数据获取难度 | 内容价值 |
|------|------------|---------|
| 小红书 | 高（无公开 API，反爬严格）| 极高（图文探店笔记）|
| 微博 | 中（有搜索 API）| 中（信噪比低）|
| 抖音 | 高（无公开 API）| 高（短视频）|
| 大众点评 | 高（反爬严格）| 高（评价数据最全）|

**可行路径**：
- 短期：不直接爬取，而是用 Web Search 间接获取公开内容摘要
- 中期：接入第三方数据聚合服务（如有）
- 长期：如果产品体量够大，申请平台开放合作
- 备选：鼓励用户自己 UGC（去过之后上传照片），逐步积累自有内容

## 七、技术演进路线

### 跟随产品阶段演进，不过度设计

| 模块 | Beta | V1 | V2 |
|------|------|-----|-----|
| **后端** | FastAPI + SQLite | FastAPI + PostgreSQL | 微服务拆分（推荐/内容/用户） |
| **AI** | DeepSeek（点评+意图） | DeepSeek + Web Search Agent | 多模型调度（意图用小模型，点评用大模型） |
| **内容** | 纯 AI 生成 | AI + 搜索结果融合 | AI + 社交平台聚合 + UGC |
| **前端** | React SPA | React + PWA（离线缓存） | 小程序 + PWA 双端 |
| **部署** | 单机 Docker | Docker + 简单 CI/CD | K8s / Serverless |
| **数据库** | SQLite | PostgreSQL | PostgreSQL + Redis 缓存 |
| **监控** | 慢请求日志 | Sentry + 基础 APM | 全链路追踪 |

## 八、增长策略

### Beta 阶段（种子期）：5-50 人

**目标**：验证核心体验链路是否 work
**策略**：
- 找 5-10 个"每天中午不知道吃啥"的同事/朋友
- 每天午饭前在群里提醒使用
- 每周收集反馈，快速迭代
- **核心观察指标**：用了之后真的去了吗？去了之后觉得选得怎么样？

### V1 阶段（冷启动）：50-500 人

**目标**：验证自发传播
**策略**：
- **分享卡片**：抓阄结果 + 人格点评做成好看的卡片，一键分享到微信群
- **场景钩子**："中午不知道吃啥？Whatever 帮你抓阄选了一家，吃货人格说值 8 分"
- **群聊场景**：做一个"帮全组选午餐"的群决策模式，拉新效率更高
- **内容运营**：在社交平台发人格点评的截图，作为内容种草

### V2 阶段（增长期）：500-5000 人

**目标**：跑通增长飞轮
**增长飞轮**：
```
更多用户使用
    ↓
更多反馈数据 → 推荐更准
    ↓
更多 UGC 内容 → 切片更真实
    ↓
更多分享 → 更多新用户
    ↓
（循环）
```

## 九、数据指标体系

### 北极星指标
**"抓阄→真的去了" 的转化率**

这个指标同时衡量了推荐质量、决策说服力、和人格点评的有效性。

### 分层指标

| 层级 | 指标 | 目标（Beta） | 目标（V1） |
|------|------|------------|-----------|
| **获取** | 日活用户数 | 5-10 | 50-100 |
| **激活** | 输入→完成抓阄 转化率 | >70% | >80% |
| **留存** | 次日留存 | >30% | >40% |
| **留存** | 7 日留存 | >15% | >25% |
| **核心** | 抓阄→导航 转化率 | >40% | >50% |
| **核心** | 抓阄→反馈 转化率 | >20% | >30% |
| **传播** | 分享率（结果页→分享） | - | >10% |
| **满意** | 反馈平均分（5分制） | >3.5 | >3.8 |

### 需要监控的健康指标

| 指标 | 报警阈值 | 说明 |
|------|---------|------|
| 意图解析失败率 | >20% | 说明 parser 覆盖不够 |
| POI 搜索返回 0 结果 | >10% | 说明搜索条件太严或地区覆盖不足 |
| LLM 超时率 | >15% | 影响体验切片加载 |
| 重新抓阄率 | >50% | 说明候选质量不行或用户不信任机制 |
| 导航 URL 为空率 | >5% | 需要修复 POI 数据处理 |

## 十一、风险与应对

| 风险 | 可能性 | 影响 | 应对 |
|------|--------|------|------|
| AI 生成的切片太假/无用 | 高 | 致命——核心差异化失效 | Beta 期人工审核切片质量，快速调 prompt |
| 用户用了一次就不来了 | 高 | 无留存=无价值 | 聚焦午餐日频场景，养成习惯 |
| 高德 POI 数据不够丰富 | 中 | 候选质量差 | 小范围搜不到时自动扩大半径 + mock 兜底 |
| DeepSeek API 不稳定 | 中 | 切片加载失败 | 已有模板降级，继续优化降级体验 |
| 社交平台内容获取困难 | 高 | V2 延期 | Web Search 作为中间方案，UGC 作为备选 |
| 选择焦虑用户不信任"随机" | 中 | 核心机制被质疑 | 抓阄不是纯随机，是加权的；用人格点评增强说服力 |

## 十二、长期愿景

**Whatever 的终态不是一个推荐工具，而是一个"决策代理人"。**

从"附近吃什么"开始，逐步扩展到：
- 今天穿什么（接天气 + 日程）
- 周末去哪玩（接交通 + 天气 + 预算）
- 这个周末看什么电影/剧
- 送什么礼物

核心逻辑不变：**你告诉我你的状态，我替你选、替你看、给你理由**。

抓阄是表象，本质是**把决策的心理负担从用户转移到产品上**。当用户说"Whatever 帮我选的"，决策的责任就转移了，焦虑就没了。

这就是产品名 Whatever 的意义——**无所谓，反正有人帮我选了**。

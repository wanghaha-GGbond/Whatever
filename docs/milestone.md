# 8周里程碑（闭环优先）

## 总目标
跑通 MVP 主链路：
输入需求 → 获取附近POI → 候选Top5 → 抓阄出1个 → 人格试玩 → 去导航 → 提交反馈

---

## Phase 0（1-2天）：范围冻结

### 目标
锁死 MVP 边界，避免需求漂移。

### 产出
- `mvp-scope.md`（在MVP / 不在MVP）
- 技术约束确认（单城市、伪多Agent、单地点输出）

### 验收
- 团队对“先闭环后优化”达成一致

---

## Phase 1（第1周）：契约先行（仅文档）

### 目标
让前端/后端/编排层可并行开发。

### 必交付
1. `api-contract.md`
2. `data-schema.md`
3. `orchestrator-flow.md`
4. `dependency-boundary.md`
5. `engineering-bootstrap.md`

### 验收
- 任一开发者可只看文档开始编码

---

## Phase 2（第2-4周）：闭环开发

### 第2周：Mock 闭环
- 前端接 mock API
- 后端接口 skeleton
- DB 建表
- 会话流转跑通

验收：
- 可演示完整 happy path（哪怕是假数据）

### 第3周：真实依赖接入
- 接高德 POI
- 接 LLM
- 基础 ranking
- persona review 生成

验收：
- 真定位、真POI、真结果

### 第4周：异常与降级
- 定位拒绝/空结果/超时/网络失败/导航失败

验收：
- 外部依赖故障下仍可返回可用结果

---

## Phase 3（第5-6周）：提质参数化

### 目标
从“能用”提升到“靠谱”。

### 交付
- `ranking-config.json`（w_dist/w_price/w_rating/w_match/w_novelty/w_risk）
- persona review 模板化（结构化输入 + 模板输出 + 轻生成）
- 反馈驱动偏好更新（预算/通勤/偏好类型/常用人格）

### 验收
- 第二次推荐对用户偏好更贴近（可对比样例）

---

## Phase 4（第7-8周）：上线准备

### 目标
完成 Beta 可观测与稳定性准备。

### 交付
- 完整埋点事件
- 初版 Dashboard
- Bug 清理 & 性能优化
- 小流量测试

### 核心指标
- 决策完成率
- 去导航率
- 重抽率
- 人格试玩点击率
- 反馈提交率

---

## 两人分工（建议）

### A（前端/体验）
- 页面与状态流转
- 异常态与兜底交互
- 埋点接入
- 导航拉起与联调

### B（后端/编排）
- API 与数据表
- Orchestrator 状态机
- 高德/LLM 接入
- ranking 配置与 persona 生成

---

## 周节奏（固定）
- 周一：只定 1 个主目标
- 周三：只查闭环断点
- 周五：必须真实演示一次

> 原则：没有 demo，就等于没完成。

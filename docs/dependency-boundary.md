# Dependency Boundary (MVP v1)

> 目标：明确“谁负责什么、失败怎么降级、合规怎么做、成本怎么控”，避免第 2 周联调卡死。

## 1. 外部依赖清单

### 1.1 高德地图（Amap）
- 用途：
  - POI 搜索（附近检索）
  - POI 基础详情（名称/类别/距离/营业状态等）
  - 导航拉起（URI/深链）
- MVP 是否接入：**是**（核心依赖）

### 1.2 LLM API
- 用途：
  - 自然语言意图解析（ParseIntent）
  - 人格试玩文案生成（Persona Review）
- MVP 是否接入：**是**（可降级）

### 1.3 评论/标签数据源
- 用途：用于“数字化探店摘要”增强
- MVP 是否接入：**否（首版先不接）**
- 替代方案：仅基于 POI 结构化字段 + 规则模板生成摘要

---

## 2. 责任边界（谁做什么）

## 2.1 高德负责
- 地点检索与基础结构化信息返回
- 导航能力（跳转）

## 2.2 高德不负责
- 不负责推荐排序
- 不负责最终地点拍板
- 不负责人格试玩内容

## 2.3 LLM 负责
- 文本理解（意图结构化）
- 文本生成（试玩说明/解释）

## 2.4 LLM 不负责
- 不直接决定最终 POI
- 不直接读写核心业务状态
- 不直接执行排序策略（排序由本地服务控制）

## 2.5 本地服务（Backend/Orchestrator）负责
- 会话状态管理
- 候选过滤、打分、约束随机
- fallback 路由选择
- 可观测性与埋点

---

## 3. 失败降级策略（必须工程化）

## 3.1 Amap 失败
- 场景：超时/4xx/5xx/配额耗尽
- 降级顺序：
  1) 使用短期缓存候选（同城/同类）
  2) 使用 mock/规则候选（模板数据）
  3) 返回 `UPSTREAM_UNAVAILABLE` + 前端可重试提示
- 要求：前端仍可完成“抓阄 -> 结果 -> 反馈”链路（哪怕是降级数据）

## 3.2 LLM 超时或不可用
- 降级到模板化输出：
  - 意图解析：关键词字典规则
  - Persona：结构化模板（review/risk/conclusion）
- 响应中标记 `fallback_used=true`

## 3.3 评论源不可用（或未接入）
- 不生成“数字化探店摘要”
- 页面展示基础判断（距离/预算/营业状态）

## 3.4 导航拉起失败
- 返回经纬度 + 备用地图链接
- 前端展示“复制地址/切换地图”按钮

---

## 4. 合规边界

## 4.1 数据采集与存储
- 仅存业务必要字段：
  - 用户输入（可脱敏后）
  - 结构化意图
  - POI 结果（最小字段）
  - 推荐结果与反馈
- 不存储外部平台原始评论全文（MVP 不接评论源）

## 4.2 数据再加工
- 允许：标签化摘要（如“可能拥挤”）
- 禁止：未经授权的原始评论二次分发

## 4.3 用户告知
- 在 Persona 模块增加提示：
  - “人格试玩为 AI 模拟判断，不代表真实到访体验。”

## 4.4 位置隐私
- 日志不落完整高精度定位（详见 engineering-bootstrap）
- 严禁输出 API Key、用户标识明文到公开日志

---

## 5. 配额与成本控制

## 5.1 预估（MVP Beta）
- DAU 假设：100
- 人均日决策次数：3
- 每次决策调用：
  - Amap：1~2 次
  - LLM：1~2 次
- 日调用量估算：
  - Amap：300~600
  - LLM：300~600

## 5.2 限流与熔断
- Amap：每用户每分钟上限 10 次
- LLM：每用户每分钟上限 6 次
- 触发阈值后：直接走 fallback

## 5.3 超时与重试
- Amap 超时：2s，重试 1 次
- LLM 超时：3s，重试 1 次
- 总链路预算：8s

## 5.4 成本保护
- LLM 优先短上下文 + 模板化输出
- 严控重试风暴（退避 200ms，最多 1 次）
- 日成本超过阈值自动切换“强降级模式”

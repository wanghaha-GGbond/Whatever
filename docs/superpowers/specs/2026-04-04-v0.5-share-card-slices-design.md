# v0.5 设计文档：分享卡片 + 切片升级

**日期：** 2026-04-04
**版本：** v0.5
**状态：** 已批准，待实施

---

## 一、目标

1. **分享卡片**：用户在结果页一键生成可分享的图片，驱动病毒式传播（V1 路线图核心增长杠杆）
2. **切片升级**：人格评价从 1 句结论升级为 4 个场景切片（到门口 / 进入后 / 体验中 / 总结），提升内容深度与可读性

---

## 二、视觉决策

| 维度 | 决策 | 说明 |
|------|------|------|
| 卡片风格 | 沉浸绿卡（A） | 品牌绿渐变满版，高辨识度，截图冲击感强 |
| 人格声音数量 | 双声版（2条） | 命运独白 + 2 条对比人格摘要，引发好奇 |
| 切片展示方式 | 横向滑动（B） | 每个切片独立卡片，移动端手势自然 |
| 生成方式 | html2canvas（前端） | 不依赖后端，Web Share API + PNG 下载兜底 |

---

## 三、功能设计

### 3.1 分享卡片

**卡片内容（固定布局）：**
```
WHATEVER · 命运已拍板          ← 小字 eyebrow
[地点名称]                      ← 大字，粗体
[类型] · [交通]约N分钟 · [预算]  ← meta 信息
"[命运独白]"                    ← 斜体引用块
[当前人格] · "[summary]"        ← 人格摘要 1
务实型 · "[summary]"            ← 人格摘要 2（固定取务实型）
WHATEVER.APP · 帮我选一个       ← footer
```

**卡片尺寸：** 3:4 比例（适合微信朋友圈和 Instagram Story）

**生成流程：**
1. 用户点击「✦ 分享这个命运」
2. 渲染隐藏 DOM 节点（`<div id="share-card-node">`，屏幕外定位）
3. `html2canvas(node, { scale: 2, useCORS: true })` → Canvas → PNG Blob
4. 调用 `navigator.share({ files: [pngFile] })`（Web Share API Level 2）
5. 若不支持（桌面 / 旧 iOS），触发 `<a download>` 下载 PNG

**2 条人格摘要来源：**
- 第 1 条：用户当前选中的人格（`selectedPersona`）的 `summary` 字段
- 第 2 条：固定取"务实型"的 `summary`（若当前已是务实型，则取"独处型"）
- **边角情况**：若第 2 条人格数据尚未加载（用户未切换过该 tab），result.tsx 在进入页面时**预加载**默认第 2 条人格（务实型）的 review 数据，确保分享时数据就绪
- 预加载在 `useEffect` 中与首次人格加载并行发起，不阻塞页面渲染

### 3.2 切片升级

**切片结构（每个人格 4 张）：**

| 切片 | 场景标签 | emoji | 内容方向 |
|------|---------|-------|----------|
| to_door | 到门口 | 🚶 | 第一印象：路程感受、门面氛围 |
| enter | 进入后 | 🌳/🍽️ | 点单/入座/环境初体验 |
| during | 体验中 | 🎯 | 核心体验：亮点或槽点 |
| leave | 总结 | 🚪 | 结论 + 情绪标签 |

每张切片包含：
- `scene_tag`（场景标签文字）
- `text`（正文，≤30字）
- `emotion`（情绪标签，≤6字，如"有点期待"/"值得等"）

**summary 字段：** 新增 1 句话（≤20字），供分享卡片人格摘要区使用，与切片内容独立生成

## 四、技术改动

### 4.1 后端

**`backend/app/services/llm.py` — `persona_review()`**

- 输出 schema 从单个 `{review, risk, conclusion}` 改为：
  ```json
  {
    "summary": "一句话结论（≤20字），供分享卡片用",
    "slices": [
      {"scene": "to_door",  "tag": "到门口", "text": "...", "emotion": "..."},
      {"scene": "enter",    "tag": "进入后", "text": "...", "emotion": "..."},
      {"scene": "during",   "tag": "体验中", "text": "...", "emotion": "..."},
      {"scene": "leave",    "tag": "总结",   "text": "...", "emotion": "..."}
    ]
  }
  ```
- `max_tokens` 从 250 提高到 500（4 个切片内容更多）
- prompt 明确要求每个切片说话风格与人格一致

**`backend/app/routes.py` — `/persona/review`**

- response `data` 新增 `slices` 数组和 `summary` 字段
- 保留旧的 `review`、`risk`、`conclusion` 字段保持向后兼容，映射规则：
  - `review` ← `summary`
  - `conclusion` ← `slices[3].text`（总结切片正文）
  - `risk` ← `slices[3].emotion`（总结切片情绪标签，或空字符串）

### 4.2 前端

**新增文件：**
- `UIUX/src/app/hooks/use-share-card.ts` — 封装 html2canvas + Web Share API + 下载兜底逻辑
- `UIUX/src/app/components/share-card-node.tsx` — 隐藏 DOM 卡片节点（绿渐变卡片 UI）

**修改文件：**
- `UIUX/src/app/pages/result.tsx`
  - 引入 `useShareCard` hook 和 `ShareCardNode` 组件
  - 人格区下方改为横向滑动切片区（替换 `PersonaReviewCard`）
  - 底部新增「✦ 分享这个命运」主按钮；「去导航」「重新抽」改为并排次级按钮
- `UIUX/src/app/lib/api.ts`
  - `personaReview` 返回类型扩展 `slices[]` 和 `summary` 字段

**修改文件（组件）：**
- `UIUX/src/app/components/persona-review-card.tsx` → 重构为横向滑动切片展示

## 五、数据流

```
用户选择人格 → api.personaReview() 
  → 后端 llm.persona_review() 返回 {summary, slices[4]}
  → 前端渲染横向滑动切片
  → 同时将 summary 存入 reviewData[persona].summary

用户点击「分享」
  → useShareCard.generate()
  → 读取 picked（地点信息）+ picked.reason（命运独白）
  → 读取 reviewData[selectedPersona].summary + reviewData["务实型"].summary
  → html2canvas(shareCardNode) → PNG
  → navigator.share() 或 download fallback
```

## 六、范围边界

**在 v0.5 范围内：**
- html2canvas 生成 PNG，Web Share API 分享
- 4 个场景切片横向滑动
- 分享卡片 2 条人格摘要

**不在 v0.5 范围内：**
- 分享链接落地页（v0.6）
- 用户 UGC 上传照片（v1+）
- 微信 JS-SDK 集成（v0.7+）
- 切片内嵌真实图片（需 Web Search，v1+）

---

## 七、验收标准

1. iOS Safari 可成功生成 PNG 并弹出系统分享面板
2. Android Chrome 可成功触发 Web Share
3. 桌面浏览器降级为下载 PNG
4. 切片横向滑动流畅，4 张卡片内容由 LLM 生成，风格与人格一致
5. 分享卡片内文字清晰无截断，emoji 正确渲染
6. `/persona/review` 响应时间 ≤ 5s（max_tokens 增加需压测）
